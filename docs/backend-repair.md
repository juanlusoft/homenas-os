## Corregido pendiente de validación del servicio real

- **Alta, HomeStore**: `assertSafeHostPath` verifica ancestros simbólicos antes de montar; `uninstallApp(removeData)` sólo borra el almacenamiento gestionado bajo `/opt/homestore/<appId>`. Antes podía borrar un pool NAS entero indicado como bind. Los demás volúmenes de usuario se conservan y requieren retirada explícita por gestor de ficheros. Archivos: `services/homestore.service.ts`, `lib/path-security.ts`. Helper probado con tmp; requiere Docker desechable para ejercicio completo de install/edit/update/uninstall y rollback.
- **Alta, Cloudflare**: ya no descarga siempre ARM64 en x86; URL específica de plataforma/CPU (probada), descarga HTTPS con `curl --fail` a directorio privado, install root 0755; env 0600 y unidad se escriben con helper privilegiado y errores systemctl se comprueban antes de persistir token. Archivo `services/cloudflare.service.ts`. Hace falta VM Debian con sudoers, systemd y cloudflared para configurar/arrancar/parar; no se ejecutó instalador ni se descargó binario en el anfitrión.
- **Media, AD**: createUser no pasa la contraseña real por argv, usa stdin como resetPassword; rechaza newline/NUL para no romper prompts. Archivo `services/active-directory.service.ts`. Requiere Samba AD de prueba para validar prompts de la versión Debian objetivo.
- **Media, exec**: helpers no declaran éxito si un proceso termina por señal sin exitCode; fallback es 1. Archivo `lib/exec.ts`. Falta regresión con runner simulado o proceso en VM; no se invocó sudo en pruebas.

## Pendiente / límites

- No se ha ejecutado instalación privilegiada, pruebas de Docker, Samba, Syncthing root/systemd ni Cloudflare sobre servicios reales; dependen de VM desechable con paquetes y permisos del destino.
- Persisten carreras TOCTOU posibles si otro proceso modifica directorios/symlinks entre validación y comando privilegiado. Los cambios rechazan escapes estáticos; protección completa requiere primitivas descriptor-relative o broker dedicado y pruebas de concurrencia con SMB en VM.
- `lib/crypto.ts` deriva cifrado de machine-id público: protege portabilidad de una DB copiada, no constituye secreto independiente. Cambiar clave/formato requiere migración compatible y backups; no se modificó sin validar recuperación de datos legacy.
- El modelo files conserva acceso de usuarios autenticados a las roots NAS `/mnt`: este repositorio no tiene ACL por share/usuario para la API. No se inventó un nuevo modelo de permisos.
- No se afirma ausencia de fallos ni funcionamiento en hardware real. Las restricciones Compose afectan configuraciones que antes pasaban controles incompletos: expandir include/extends a un único YAML revisable antes de importarlo.

Instalación/arranque completos y agentes restantes se documentan en el informe coordinado. Para backend aislado: definir `HOMENAS_DATA_DIR=$(mktemp -d)`, ejecutar desde `apps/backend` el comando de desarrollo de package.json y comprobar `/api/health`; no llamar operaciones de sistema desde ese proceso. Pruebas automatizadas anteriores son la referencia de validación segura local.
